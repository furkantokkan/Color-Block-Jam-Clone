# Booster Gameplay

This document fixes the design of the playable booster flow: Time Freeze, Rocket, Hammer and Vacuum on the gameplay bar, and the starting Extra Time and Rocket. Every implementer follows these decisions; a change to one of them goes through the task's decision owner first.

- Task: `production/tasks/TASK-20260927-004448215-54655902-booster-gameplay-flow` (contract and handoff).
- Decision log: PROJECT.md DEC-146 (Rocket split), DEC-147 (Hammer, Vacuum, casts), DEC-148 (time boosters), DEC-149 (intent, save, opening), DEC-150 (HUD), DEC-151 (in-game purchase popup), DEC-152 (template cast particles). Verification: [booster gameplay verification](verification/booster-gameplay/README.md).
- Related: [Gameplay: Drag and Gate](Gameplay-Drag-And-Gate.md), [Block Effects Architecture](Block-Effects-Architecture.md), [Hub and Player Data design](Hub-And-Player-Data-Design.md), [booster motion](art/boosters/motion/README.md), PROJECT.md (Runtime Lifecycle, Architecture Rules, Performance Rules), PRD section 7.10.

## 1. Product rules (as decided for this task)

- **Rocket** removes exactly one tapped cell. The remaining cells may form several 4-connected pieces; each becomes an independent block with its own runtime ID and state, the parent's colour and source, and a copy of the parent's Ice count (and Arrow axis when Arrow is live). The final or only cell of a block is refused (AC-BST-3.3 kept); a refused target spends nothing. Starting Rocket samples one eligible cell, now including cells that split a block.
- **Hammer** removes the tapped block whole, whatever its footprint, including an active Ice shell. It never splits and raises one `BlockRemoved`.
- **Vacuum** removes every on-board block of the tapped block's colour in one command, Ice and Arrow blocks included, raising one `BlockRemoved` per block in ascending runtime ID. It shows no crosshair.
- **Time Freeze** holds the main countdown for 10 Playing seconds with its own 10-to-0 counter and screen-edge frost. It adds nothing to the main time. A second activation while a freeze runs is refused before any spend.
- **Extra Time** is pre-level only: +`BonusSeconds` once at opening, before Rocket.
- A valid use captures an immutable intent, enters `Paused(Saving)`, persists one stock debit, then applies once as the first command of the first resumed command phase, before the timer. Selection, cancel, switching tools and refused targets are free.

## 2. Decisions

| # | Decision | Reason |
| --- | --- | --- |
| B-1 | **Runtime footprints live in `BoardState`.** One flat `Cell[]` buffer holds every block's relative cells in per-slot slices (start, count), plus per-slot bounds, colour, source (authored index), origin and status. Slot capacity is `LevelModel.TotalCellCount`, the sum of authored cell counts, computed once in `LevelModel.TryCreate`. | No allocation in Playing; one owner for occupancy and footprints. Every live block keeps at least one cell and each Rocket removes one, so the number of IDs ever created is at most the initial cell count. |
| B-2 | **Runtime IDs.** IDs `0..B-1` are the authored indices (DEC-115 ties, replay and existing commands unchanged). A split appends new IDs; IDs are never reused within an attempt. `IBoardReader.BlockCount` is the number of IDs issued so far; `LevelModel.BlockCount` stays the authored count. `Reset()` restores the authored slices and `BlockCount = B`. | Existing `for block < BlockCount` loops, picking and replay extend naturally. Fragments lose pick ties to authored blocks, which is deterministic (extension of DEC-115). |
| B-3 | **`IBoardReader.GetFootprint(int block)`** returns a `readonly struct BlockFootprint` (`CellCount`, `GetCell(i)`, `MinX/MaxX/MinY/MaxY`, `Depth(Side)`, `Color`, `Source`). Every Domain rule (MoveRules, MoveReach, DragResolver, ExitRules, BlockPicker, PreviewBoard, BoardState) reads footprints through it. `Model.GetBlock` is used only for authored provenance and on Home. | One conversion point; no rule can read a stale authored footprint after a split. |
| B-4 | **Split algorithm.** `BoardState.RemoveCell` (internal, added to the architecture test's mutator list) clears the cell, labels the remaining cells of the block into 4-connected components by BFS over the occupancy grid with scratch buffers allocated in the constructor, and stable-partitions the parent slice by component. The component holding the first remaining cell in slice order keeps the parent ID; the others take new IDs in the order of their first cell. Children keep the parent's current origin with unchanged relative cells, so world cells do not move. `RequiredRemaining += components - 1`. | Deterministic IDs for replay (AC-6); zero visual jump; allocation-free. |
| B-5 | **Event shape.** `FootprintChangedEvent` gains `Parent` and `RemovedCell`; the parent's own event has `Block == Parent`, each child's has `Block != Parent`. Order: parent first, then children in ascending ID. `BlockRemovedEvent` gains `Cause` (`CommandKind`) and `Source` (the tapped block for Vacuum, the block itself for Hammer). `BoardEvent` carries `Parent` and `Cause`; the removed cell rides in `From`. For a `Removed` event, `BoardEvent.Parent` holds the event's `Source` (the tapped block for Vacuum, the block itself for Hammer). The single-argument constructors stay and default the new fields. | No fifth `IBoardEventListener` method, so IceRules and the test listeners keep compiling. A split is neither an exit nor a removal, so Ice counters and a future barrier listener stay correct. |
| B-6 | **Commands.** `CommandKind` appends `RemoveCell = 2` (Rocket), `RemoveBlock = 3` (Hammer), `RemoveColor = 4` (Vacuum). `GameCommand` gets factories: Rocket `(block, From = block origin at capture, To = absolute cell)`, Hammer `(block, From = origin)`, Vacuum `(tapped block, From = origin, Option = (int)colour)`. `CommandOutcome` appends `FinalCell = 11`, `NotBlockCell = 12`, `ColorMismatch = 13`. Handlers are internal in `Domain/Boosters`, registered next to `MoveBlockHandler` in `BoardSimulation`; each validates everything first, pre-checks event-log room, then mutates once. Targets are not drag-gated: Ice and Arrow blocks are valid. `Exited`/`Removed` blocks give `NotOnBoard` (an exit commits `Exited` at once, so a mid-exit block is already rejected). | CommandExecutor stays the only board mutation path (DEC-122); logged boosters replay. |
| B-7 | **Capacities.** `BoardEventLog` capacity is `TotalCellCount + 4` (still 2 + 4 for two 1-cell blocks). `CommandLog` stays 1,024. | A Vacuum can remove at most every live block, which is at most the live cell count. |
| B-8 | **Time boosters are clock operations, not GameCommands.** `Domain/Session/AttemptCountdown` implements `ICountdown` and `IFreezeCountdown` (`TryFreeze(float seconds)`, `IsFrozen`, `FreezeRemaining`, `AddSeconds(int)`). A tick consumes the freeze first and passes only the leftover delta to the main clock; it returns true once when the main clock reaches zero. `SetPaused` and `Stop` cover both clocks; `Start` clears any freeze. The session applies Time Freeze and Extra Time in the same intent step as board boosters. It replaces `InactiveCountdown` in the Game scene. | The command log is a board log; the clock is session state. Keeping the freeze inside the countdown means Suspend, Resume, Teardown and Won already stop both clocks without new session collaborators (the exact-journal tests stay valid). |
| B-9 | **Displayed seconds round up.** Main timer text is `m:ss` of `ceil(remaining)`; the freeze counter shows `ceil(freezeRemaining)`. Both come from prebuilt string tables (main: 0 up to authored time plus the largest Extra Time bonus; freeze: 0 to `ceil(DurationSeconds)`; stock: 0 to 99) and change only when the integer changes. | AC-3 ("after four Playing seconds it shows six"); Performance Rule 8 without a Gameplay ZString reference. |
| B-10 | **Ice.** `IceRules` gets a capacity overload (arrays sized to `TotalCellCount`); `OnFootprintChanged` for a child (`Block != Parent`) copies the parent's initial and remaining counts. `OnBlockRemoved` stays a no-op. `IceEffectModule` passes the capacity. Presentation: `BlockIceOverlay` becomes recomposable from prewarmed per-kind Ice tile pools sized by the authored footprint's reachable capacity; `BlockIceOverlays` holds, per frozen authored block, a bounded shell pool for its maximum simultaneous fragments; `IceCounterLabels` gets capacity slots and `SetFootprint`. Existing constructors and `Attach` signatures stay (Editor preview and `BlockIcePresentationTests` use them). | AC-BST-3.5 (Rocket keeps the counter), no fragment index out of range, no Instantiate in Playing. |
| B-11 | **Target rules** (pure, `Domain/Boosters`). Rocket: the cell's occupant is an on-board block with at least 2 cells. Hammer and Vacuum: the block is on board. Starting Rocket candidates: every eligible cell, blocks in ascending ID, cells in slice order; one uniform sample from an injected seed. | One rule for in-game and opening use; deterministic tests. |
| B-12 | **Targeting input.** Targeting has its own mode (`None`, Rocket, Hammer, Vacuum) owned by a Gameplay object that holds no board state. While a mode is set, `DragInputRouter` starts no drag. It resolves the press on release with a direct hit only: `TryScreenToBoard`, `InteractionArea`, then `GetOccupant(round X, round Y)` on the committed board. Never the nearest-footprint fallback (DEC-91). An empty cell, wall, gate, border or outside press cancels. An on-board but ineligible block (Rocket on a 1-cell block) is rejected: the mode stays and the existing blocked-drag shake plays. The same button, the banner close button and Android Back (a code-built `<Keyboard>/escape` action polled in the tick) cancel. Switching tools is free; a Time Freeze tap while targeting cancels targeting first. Suspend, Teardown and Won clear the mode through `DragInputRouter.Reset`. | Contract lines 30-34; references 02, 03, 17; single pointer reader per tick. |
| B-13 | **Intent and save.** `BoosterIntent` (readonly struct: attempt generation, `BoosterId`, `GameCommand` for board boosters, freeze seconds) is validated and captured, then `LevelSession.TrySubmitBooster` clears targeting, interrupts the drag and **discards** its pending move, and enters `Paused(Saving)`. The accepting tick returns at once. The app-scoped debit is awaited by `BoosterUseCoordinator` (one owned task, faults logged, own token). `LevelSession.CompleteBoosterCommit(generation, committed)` ignores stale generations, latches a committed intent, and resumes only when the pause reason is still `Saving`. After backgrounding, the committed intent waits for an explicit Resume and applies once then; a failure stays paused with no effect. Resume, Restart and Home are refused while the write is unresolved. The interim foreground resume (`NoPauseOverlay`, DEC-116) waits for the write to resolve instead of resuming during it. Home or Restart after a committed but unapplied intent discards it without refund. | DEC-92, AC-10, AC-11; PROJECT.md "Clear drag/pointer commands" for `Paused(Saving)`. |
| B-14 | **`IBoosterConsumer.ConsumeAsync(IReadOnlyList<BoosterId>, CancellationToken)`** on `PlayerSaveService`: one charge per listed ID, duplicates and unknown IDs are `InvalidRequest`, every ID validated before one snapshot, one store write and one revision. The caller token only cancels the wait for the write lock; a started store write gets the service lifetime token and completes (`Consumed` or `SaveFailed`). A spent charge is stored as a present 0, so reload never reseeds. | Matches the purchase transaction; an attempt ending cannot cancel a committed write (PROJECT.md Ownership). |
| B-15 | **Tick order while Playing.** 1) clear events; 2) apply the committed intent or the opening intents once (Extra Time, then Rocket); 3) the parked drag move; 4) unless the opening hold runs: pointer router (drag or targeting) and command source; 5) if the state left Playing, return; 6) Won check; 7) timer, unless the opening hold runs; 8) view sync and HUD clock values. | RULE-18, AC-BST-0.4, AC-6.11. |
| B-16 | **Opening.** On Home, the Game scene prepares and validates the board, samples the Rocket target, and commits the combined debit of the applicable starting boosters in one `ConsumeAsync`; a Rocket with no candidate is dropped from the debit. `LevelSession.Play(in OpeningPlan)` then enters Playing; an intro of Playing time (default 1.2 s) dims the screen with one icon per starting booster and fades out in its last 0.2 s, the next command phase applies Extra Time and the Rocket command once, and a hold (default 0.9 s) lets the Rocket cast fly; intro and hold keep the countdown, drag and HUD booster input off (DEC-166, revised 2026-09-28: the Rocket is thrown after the dim, input opens after the Rocket). Pause keeps the hold's progress; Teardown cancels it. Backgrounding during the Home commit makes the loader wait for foreground before Play and reuse the committed plan. Direct Game Play, Restart, Next Level and Editor test play start with no selection. | Contract AC-13, AC-14; PROJECT.md starting-booster rules. |
| B-17 | **Starting selection seam.** The Game scene reads its starting selection from `IStartingBoosterSource` (default: none). The pre-level launch task maps its `LevelLaunchRequest` onto it; this task does not rebuild Hub scope. Production seed: a scene-bound seed source created per attempt; tests inject a fixed seed. | Hub pre-level launch is not implemented yet (contract stop condition). |
| B-18 | **In-game purchase.** A zero-stock tap cancels targeting, asks `IInGamePurchaseHost` to show the purchase for that definition and enters `Paused(Purchase)`, whose Suspend holds the countdown and the freeze. With the HUD document wired the host is `InGamePurchaseHost` over the shared purchase popup (`ColorBlockJam.UI`, DEC-136) inside the HUD (B-32). Buy runs `IBoosterShop.PurchaseAsync` for the definition's configured offer inside the shared presenter and is disabled while `IsSaving`, so a second submission never reaches the shop. Success refreshes the bar's badge through the reactive stock, keeps the popup open and never casts or selects. The close button, a scrim tap and Android Back hide the popup and call `LevelSession.ClosePurchase`, which resumes unless backgrounding latched the pause; the ordinary background rules then apply. Leaving `Paused` any other way (Home, Restart, a foreground resume) hides it through the coordinator's state subscription. A purchase result after the popup hid shows nothing. Without the HUD document `UnavailablePurchaseHost` stays bound: the button plays blocked feedback and nothing pauses. | AC-12; user approval of 2026-09-27 (DEC-151). No second economy, popup or session state. |
| B-19 | **Board presentation.** `BoardPresenter` sizes its per-block arrays to `TotalCellCount`, reads runtime footprints, and looks up source type and colour by `GetFootprint(block).Source`. It handles `FootprintChanged` (recompose the parent root through a non-throwing `BlockPiece.TrySetCells`; spawn each child root from the same source-type pool at the parent's origin; re-attach Ice shells, labels and Arrow markers) and `Removed` (keep the root through a bounded removal tween). Pool headroom per block is its maximum simultaneous fragment count minus one: the maximum independent set of its footprint graph, enumerated up to 12 cells, else cell count minus one. `ExitFragmentPlacement` and exit travel use runtime bounds. | AC-6, AC-16; any nonempty cell subset is reachable, so the independent-set bound is exact. |
| B-20 | **Casts.** One presentation owner forwards from `BoardPresenter` (the ExitFragments pattern, DEC-131) and holds two pooled instances each of `HammerEffectView`, `RocketEffectView` and `VacuumEffectView`, warmed on Home under the board root. Every cast enters above the HUD's booster bar (user request 2026-09-28): the HUD implements `IBoosterCastAnchor` (the bar's top centre as a viewport point), the Game installer passes it to `BoardPresenter.SetCastAnchor`, and the launch is the board-floor point under that point; without a HUD or a laid-out bar it falls back to one cell below the lower board edge. Hammer: root at the block's top centre, facing the camera; the mallet stays upright on screen (user request 2026-09-28): it swings in the root's upright plane along the view, flies in from the launch in its strike pose (head cap above a full-length handle, reference 16), raises its head, then its +X face comes down on the block top; the removed block's root stays until contact (0.74 of the cast), then shrinks for 0.1 s. Rocket: launched from the launch point to the removed cell's top; the domain splits at once, but the parent's root keeps its whole old footprint and the new parts get no root until the nose touches the cell (`RocketEffectView.k_noseFraction`, user request 2026-09-28), when one Home-allocated delayed cue per parent recomposes it and spawns its parts. Any later event on those blocks, a hold, a refused press or `CompleteRocketHits` shows the split early; Suspend pauses the cue and Teardown drops it; without a free cast the split shows at once. Vacuum: camera-facing, its drawn canister bottom (`VacuumEffectView.BaseDepth`) on the launch's view ray, moved toward the camera until the sprite plane is in front of the near wall tops so the lower wall and gates never hide its hose or nozzle; every target, the tapped block included, keeps its colour and shows the white Highlight Plus outline (user order 2026-09-28; it no longer turns white), and every removed root moves into `IntakePosition` while shrinking, from 0.13 to 0.86 of the cast. All removal tweens target block roots, so `SetTweensPaused`/`StopTweens` already cover them; cast views are Suspended, Resumed and Stopped by the owner. `FinishSeconds` includes removal tweens and remaining cast time, capped at 0.8 s by the session. | DEC-93, AC-8, AC-9; domain never waits for visuals. |
| B-21 | **HUD host.** A new root GameObject `Gameplay HUD` after `Board effect counters` in the Game scene (outside `SceneScope`) carries a `UIDocument` on `BoardOverlayPanelSettings` (sort order 30, `Gameplay/UI/GameplayHud.uxml`). `GameSceneInstaller` references it in `m_hudDocument` and adds it to the pointer-veto list itself (the serialized `m_uiDocuments` stays empty), so UI presses never reach the board. An `EventSystem` with `InputSystemUIInputModule` sits under `SceneScope`. The module has no serialized actions, so its `OnEnable` assigns fresh default actions in the current input state: a reference to the package's shared `DefaultInputActions` asset kept controls resolved against a long-running Editor's earlier devices, and enabling it after `InputTestFixture` swapped the input state threw `IndexOutOfRangeException` in `InputManagerStateMonitors` (`GameSceneUiInputTests` reproduces it). The HUD is plain C# (view, presenters) bound in the scene container and shown on Home by `GameAttemptLoader` through `TryResolve`. | DEC-132 conventions; the Ice test's reflective `Load` with a small container still works. |
| B-22 | **HUD layout.** Top: the timer band (`bg_gameplay_time_holder`, `ic_time`, `m:ss`) with the freeze counter under it; the targeting banner (`bg_popup`, `bg_popup_header` title plaque, icon, instruction, `btn_popup_close`) sits **below** the timer band instead of replacing it, so the clock and freeze counter stay readable (AC-BST-1.5). States are USS classes (`--selected`, `--empty`, `--frozen`, `hud--targeting`) plus `SetEnabled(false)` while not Playing, during the opening hold, while a write is pending or `IBoosterShop.IsSaving`, and for Time Freeze while frozen. | References 01-04, 13, 16; contract AC-1, AC-2. |

## 6. Deviations recorded during implementation

Each item changes or refines a decision above; the package reports of the session, presentation and HUD work are the source.

**Session and input (B-8, B-12, B-13, B-16, B-18)**

- The target sink attaches through `BoosterTargeting`. `DragInputRouter`'s `[Inject]` constructor is `(IPointerSource, IUiPointerFilter, IBoardProjector, BoosterTargeting)`; the coordinator calls `BoosterTargeting.Attach(this)` in its constructor and detaches in `Dispose`. The router hands a target to `BoosterTargeting.TrySubmit(attempt, cell)`, which returns `Empty` with no mode or sink. A router-owned sink would form the DI cycle session, router, coordinator, session. The 3-argument constructor stays, with targeting off.
- A targeting press is taken on Down and resolved on Up at the press position. A `Cancel` pointer phase is not a tap: it resolves nothing and keeps targeting.
- Leftover hold time goes to the countdown: in the tick where the opening hold ends, the Playing time left after the hold reaches the main clock (freeze arithmetic). The router and the command source still skip that tick.
- The coordinator hides the purchase host whenever the session state leaves `Paused` (one `State` subscription), so the interim foreground resume (DEC-116) cannot resume play under an open purchase popup.
- `LevelSession.Play(in OpeningPlan)` throws `InvalidOperationException`, before any state change, for a plan with Extra Time when the countdown is not an `IFreezeCountdown`. `StartingBoosterPreparer` checks `LevelSession.SupportsTimeBoosters` and drops Extra Time first, so nothing is spent that Play would refuse.
- `LevelSession.IsHomeBackgrounded` is an `IReadOnlyReactiveProperty<bool>`, so the loader can read `.Value` (B-30) or subscribe.
- The accepting tick of a booster use allocates once, for the coordinator's save-task state machine. It is the transition into `Paused(Saving)`, not steady Playing; the zero-allocation tests cover the steady targeting and frozen ticks.

**Presentation (B-10, B-19, B-20)**

- The Rocket cast starts on the parent's own `FootprintChanged` entry (`Block == Parent`), because `BoardEvent.FootprintChanged` carries `Cause = None`; the removed cell comes from `BoardEvent.From`.
- `IceEffectModule` computes the capacity as the sum of the `LevelData` block cell counts (equal to `TotalCellCount`); `IceEffectView.TryPrepare` refuses a mismatch.
- Ice tiles come from one Onity pool per piece kind inside each shell; the old constructors warm exactly their own pieces, so Editor-preview object counts are unchanged. `BlockIceOverlays.TryAttach` returns false instead of throwing on exhaustion. A removed block's counter label hides at once; its shell shrinks with the root.
- Fixed layout defaults for projected Ice counters and the Level Complete arc's row direction live in USS. Runtime writes only camera-projected counter/reticle positions and sizes, safe-area insets, progress/state changes and measured per-letter transforms; the code-created Editor preview explicitly loads `Common.uss` for its generated labels.
- Vacuum removal uses a tracked `Tween.Position` to the intake plus an untracked `Tween.Scale` with the same timing on the same root; both stop with `StopAll(root)`. Without a free Vacuum instance or a catalog the removal falls back to the quick 0.1 s shrink.
- Cast views sit directly under `EnvironmentView.BoardRoot`, warmed once on the first build and kept across levels (the ExitFragments pattern), two per kind; a cast is skipped when both are busy.
- Arrow marker headroom is exact per variant (`FragmentCapacity.AddArrowMarkerCapacity`), so the Arrow test level warms 5 markers instead of 2. The Game scene passes no authored Arrow data yet, so it warms none.
- Exit fragment emitters still warm min(authored block count, 4); simultaneous part exits beyond that skip their bursts.
- `BoardPresenter` creates `BoosterCasts` only in its 5-argument constructor, which adds `BoosterCatalog` (bound in `ProjectContext`); the 2- and 4-argument constructors create no casts. The frost later moved `[Inject]` to a 6-argument constructor (below).
- The Ice refinement merged from the shared workspace moves the frozen block's root, carrying its shell, instead of the shell alone, so the studs stay aligned. `BlockIceOverlay.TrySetCells` stops that punch through the same restoring stop as Teardown's `StopTweens`, so a Rocket recompose of a frozen parent, which never settles later, leaves its root on its cell.

**HUD and composition (B-17, B-21 to B-25, B-27)**

- Frost joins the `BoardPresenter` fan-out through a 6-argument `[Inject]` constructor that adds `TimeFreezeFrostView`; `SetTweensPaused` and `StopTweens` forward to it. Onity cannot inject a raw `Camera` or `Material`, so `TimeFreezeFrostContext` (camera, material) carries them. The 5-argument constructor stays public without `[Inject]`.
- `GameAttemptLoader` implements `IStartingBoosterSource` and is bound as that instance (the Composition folder allows only the installer and the loader). `public static ReadStartingBoosters(LevelLaunchRequest)` maps the request; an ID that is not a starting booster logs an error and selects nothing. `Load(IResolver, LevelCatalog)` stays synchronous with no selection, and the HUD is resolved only through `TryResolve`.
- `GameSceneInstaller` binds one `AttemptCountdown` as `ICountdown` and `IFreezeCountdown` (replacing `InactiveCountdown`) and gains the serialized fields `m_hudDocument`, `m_frostMaterial` and `m_reticleTexture`. It adds the HUD document to the pointer-veto list itself, without duplicates. A missing HUD document binds no HUD and logs nothing.
- Booster buttons are named generically `booster-button-0..3` and filled in catalog order filtered by `InGame`; the banner copy of B-23 lives in `BoosterInstructions`.
- Blocked feedback on a HUD button is a USS class flash (tint) removed by its own `TransitionEndEvent`, not a PrimeTween; a disabled or hidden button drops the class.
- A Rocket target on a plain block used to be rejected silently: `BoardPresenter.ShowBlockedDrag` now punches the root once for a block no drag gate holds. A gated block gets no presenter punch: the Ice view punches the frozen root once, carrying the shell, and returns it to its cell when the punch ends or Teardown stops it.
- `Game.unity` keeps its own `EventSystem` (B-21), because direct Play and Test Level have no other scene to supply one. The shipped flow loads scenes single (Init, Hub, Game), so it never meets Hub's `EventSystem`. A test that loads Game additively while Hub is still loaded makes Unity log "There can be only one active Event System". That is the test's own arrangement, so no runtime guard is added; `BoardArtContainerTests` after `HubStartupFailureTests` is the known case, reported to its owners.
- The in-game HUD's first Rocket crosshairs write no new inline style: `RocketReticleView.Reserve` pre-writes `left`, `top`, `width` and `height` on Home, and `GameplayHudView` pre-writes the banner icon and skips an unchanged icon.
- `ic_target.png` is imported as a fixed Sprite with Read/Write on, RGBA32 and Max Size 256, because the white reticle copy reads its pixels on Home (`Texture2D.isReadable`, `GetPixels32`). Without Read/Write the layer logs one warning and shows only the black outline.
- Booster's own launch tests (`GameSceneBoosterCompositionTests`) debit an isolated, gated stock and never the project's Editor in-memory player store. Hub's `HubLaunchTests.LaunchRequest_PlaysTheRequestedIndex_InsteadOfTheSerializedOne` launches Game with Extra Time and Rocket through the real project scope, so the opening's Home debit (B-16) spends both seeded charges for the rest of the run, and later Hub tests that need that stock fail or report Inconclusive. The debit is correct (DEC-78, DEC-92); the missing stock reset between Hub tests is a Hub test-isolation defect, reported to the Hub owner.
