# D-001 — Plain bound draft fields do not update the preview

- Relation: AC_FAILURE (AC-3)
- Dedupe key: level-preview/draft-publish/plain-bound-fields
- Found by: independent verifier, 2026-09-25 (evidence.md, "Finding (AC-3)")
- Symptom / repro: In the Level Editor window, change Width (or Height, Timer, Name) of the selected level with the LevelEditor scene open. The preview keeps the old size. Cause: the publish hook listened only to `SerializedPropertyChangeEvent`, which only `PropertyField`s raise; plain bound `IntegerField`/`TextField`s raise only `ChangeEvent<T>`.
- Fix: `LevelDatabaseWindow.LoadSelectedDraft` tracks the whole draft with `m_draftFields.TrackSerializedObjectValue(m_draftObject, _ => SchedulePublish())` (owner: `m_draftFields`; stop point: `Unbind` in the next `LoadSelectedDraft`).
- Verification (live Editor, MCP HTTP, 2026-09-25):
  - Width set to 6 through the bound UI field: the draft became 6x5, and the preview rebuilt to layout 6x5 (74 pieces).
  - Width set back to 4: the preview returned to 4x5 (56 pieces), `HasDraftChanges` is False, and `LevelEditor.unity` is unchanged (sha 3e743628…02de9).
  - Tests: LevelPreview EditMode 9/9 (job 6b9e90a93cb9438f86641bc48b433deb). DatabaseControls, LevelDatabaseAddressables and AddressablesSettingsRegistration 18/18 (job 1aabe67914204c06b53ef1df734be034).
- Related observation (not this task, handed to the level-editor-shell task): after a domain reload while the Editor is unfocused, the recreated window can leave the Name, Width, Height and Timer fields unbound (showing 0) until the level is reloaded. This existed before this task and was seen in the user's screenshot during a test run.
