## Observation

The project-scope load uses only the build token without a shape library, and the build/cache tokens with one. Onity's normal build supplies no cancellation token. Neither path is tied to the installer component, so destroying it alone cannot stop its load.

## Reproduction

1. Copy the real ProjectScopeInstaller settings onto an active unsaved test object and register its bindings in a separate OnityContainer.
2. With and without a shape library, assign an unsaved empty-GUID LevelDatabase, destroy the installer owner, then build the container.
3. Separately, assign the library and a cache store that waits in ReadAsync; start the build, wait for that read, then destroy the installer owner while keeping the container alive.
4. Check that the first case cancels before loading and the second cancels the pending read/build without a cache write.

## Expected and actual

- Expected: destroying the installer cancels its load in both branches; a pending cache read stops without a write and the loader seals its catalog.
- Actual: the installer token is absent; the deterministic pre-load case reaches the empty-GUID database error and the pending-read case has no installer cancellation signal. Focused runtime reproduction follows before the production fix.
