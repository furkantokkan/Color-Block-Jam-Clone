- Expected behavior:
  1. **Freehand stroke.**
     - With the Pen and no armed piece, pointer down on a free cell starts a stroke. Each move adds the free cells it crosses; a fast move steps cell by cell so the stroke stays 4-connected. Occupied cells are skipped.
     - The stroke shows as a ghost in the selected colour. Release creates one block through `TryPlaceBlock` as one undo step. Esc cancels the stroke.
     - A stroke that is not 4-connected, has more than 25 cells, or does not fit a 5x5 box is refused with a designer message and changes nothing.
  2. **Shape id.**
     - The canonical footprint is the smallest normalized, sorted cell list among the eight rotations and mirrors.
     - If a library piece has the same canonical footprint, the block gets that piece's `TypeName` and keeps its drawn cells.
     - Otherwise the id is `Custom_` plus the 7 uppercase hex digits of the canonical footprint's 25-bit occupancy mask in a 5x5 box (row-major from the bottom-left). The same footprint always gets the same id and a different one never does.
     - Rotating or mirroring a custom block keeps its id.
  3. **Palette.** A Custom section after the library tiles lists every distinct custom id used in the active level database, plus "+" pieces applied in this window session and not yet placed, drawn with the same centred thumbnail layout and stampable with the Pen like a library piece. Custom tiles have no ×, because they are not library entries. An unplaced "+" piece lives only in the window's serialized state; it is never written to level JSON until a block uses it (D1-A).
  4. **Issues.**
     - `LevelDraftIssues` gets a `Collect(level, catalog)` overload. The library and custom-id checks are warnings, so `HasError(Collect(...))` still equals `LevelData.Validate` failing.
     - It warns for a block whose `shapeId` is neither a library piece nor the custom id of its own canonical footprint, for a library id whose piece was deleted, for a library block whose cells are no longer a rotation or mirror of the library footprint, and for a custom footprint outside the runtime learning limits.
  5. **"+" tile.**
     - The last item of the Blocks palette is a "+" tile added after the tile loop and kept out of `m_tiles`/`m_choices`. It raises a new `PieceCreateRequested` event, wired next to `ShapePicked` and `ShapeDeleteRequested`.
     - Clicking it opens the Piece Editor in level-piece mode through `ShowLevelPiece` with the open level id, a new piece id and a one-cell draft.
  6. **Linked Piece Editor (Level Editor side).**
     - Clicking a library tile calls `ShowLibraryPiece(typeName)`; clicking a Custom tile calls `ShowLevelPiece` with the level id, piece id and cells. The Piece Editor's own discard prompt applies. Neither call writes library data.
     - The Level Editor subscribes to `LevelPieceApplied` and `LibraryCommitted` in `OnEnable` and unsubscribes in `OnDisable`.
     - On `LevelPieceApplied` for the open level, it validates the cells (4-connected, at most 25, inside 5x5), assigns the id by rule 2, lists the piece in the Custom section and arms the Pen with it. An event for another level id is ignored. An invalid footprint is refused with a message and changes nothing.
     - If the applied piece is already used by placed blocks, every such block is re-stamped with the new footprint, keeping its rotation or mirror, and relabelled to the new id in one undo group. If any block would go off-board or cover a void or a board object, nothing changes and the banner lists the blocks (D3-A). (Revised 2026-09-26, D3-B.) A block that would overlap another block does not refuse the change: it is re-stamped and the overlap is marked (item 9).
     - On `LibraryCommitted`, it calls `RefreshShapeCatalog(false)` and re-runs the checks. Blocks in the open level whose `Custom_` footprint now matches a library piece are relabelled to its `TypeName` in one undo step (D4-A).
  7. **Conflict warnings and Re-stamp.**
     - A deleted or changed library piece in use shows a warning row per affected block in the open level and a banner with the count of affected blocks in other levels (D6-B, `CountBlocksUsing`).
     - The banner has a **Re-stamp** button for changed footprints. Re-stamp finds the rotation or mirror that mapped the old footprint onto each block, applies it to the new footprint through the existing rotate/mirror helpers and `TryReplaceBlockCells`, all in one undo group. It is refused whole when any block would go off-board (D3-A); (revised 2026-09-26, D3-B) an overlap with another block is applied and marked (item 9). A block re-stamped onto a void cell shows the `Validate` error and Save Level refuses.
     - Nothing re-stamps automatically (D2-A).
     - The checks re-run on `LibraryCommitted`, `OnFocus`, undo/redo, level load and every draft change.
  8. **Docs.**
     - `docs/Level-Editor-Design.md` describes the stroke, the id rule, the "+" tile, the Custom section, the Piece Editor link and the conflict/Re-stamp rules.
     - `docs/Level-Data-Format.md` documents the `Custom_` id convention next to the runtime-learned shape rule, coordinated with the runtime-shapes-from-json owner.
     - (Revision 2026-09-26.) `docs/Level-Editor-Design.md` describes the overlap marks and the Save gate of item 9.
  9. **Overlap marks and the Save gate (revision 2026-09-26, D3-B).**
     - A re-stamp (item 6, item 7 and the click-to-grow re-stamp of scenario 13) may leave blocks sharing board cells. It never adds an overlap through place, move, rotate, mirror or Piece Type, which keep refusing it.
     - The canvas label of every block that shares a board cell with another block reads `<s>B1</s>` (the id in capitals inside the rich-text strikethrough tag); every other label keeps its plain id. The mark comes from the draft on every change, including undo, redo, Raw data and a level load.
     - The status of a re-stamp that leaves an overlap names the overlapping blocks and says that Save Level waits until they no longer overlap. The issues list keeps its existing overlap errors.
     - Save Level is disabled while `LevelDraftIssues.HasError` holds for the issues list, with a tooltip saying that the errors in Issues must be fixed first; it is enabled with its normal tooltip when no error is left and a level is open. `SaveLevel` still refuses an invalid draft through `Validate`.
