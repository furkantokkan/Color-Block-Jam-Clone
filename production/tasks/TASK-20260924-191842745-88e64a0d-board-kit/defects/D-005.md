## Observation

After saving a new piece ("12. New Piece Test"), pressing × (Delete selected piece) makes the Editor unresponsive
("Hold on... Importing assets") and the Piece Editor reports "Wait for compilation before importing new enum
identities." The piece is not removed until the compile has finished and Delete is used again.

## Reproduction

1. Piece Editor, BlockShapeLibrary active. Paint a piece, name it (for example "New Piece Test") and Save piece.
   Save writes `BlockShapeType.cs` (new ID 30) and starts a script compile.
2. Select the new piece and press × while that compile runs (or right after it).
3. Delete is refused with "Wait for compilation before importing new enum identities."; nothing is written
   (`BlockShapeLibrary.json` keeps ID 30, last write 11:34:13). Otherwise a delete of an identity that is on disk
   but not yet compiled rewrites and force-imports the unchanged enum file, which starts another compile.

## Expected and actual

- Expected: Delete removes the record from the selected JSON immediately. It reserves the enum value, so it
  needs no enum write, no enum import and no compile, whether or not a compile is running.
- Actual: Delete compares identities with the compiled enum instead of the enum file on disk, treats the
  just-saved identity as new, refuses during compilation and would otherwise re-import `BlockShapeType.cs`.
