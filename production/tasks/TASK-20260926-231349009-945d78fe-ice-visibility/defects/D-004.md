## Observation

The preview displays the count badge over a normal pink block, with no visible frost shell. The shell's graph is valid enough to compile and expose its properties, but its generated scalar constants output zero.

## Reproduction

1. Preview the current unsaved level with Ice count 1 on B2.
2. Capture the actual GameView with its UI overlay; see [pre-repair preview](../evidence/preview-user-draft-portrait-1.png).
3. Inspect `BoardIceAssets.Graph.Number` and the serialized Float nodes: input slot 1 has value 0 even where its default is 1, 0.2 or 0.65.

## Expected and actual

- Expected: A visible translucent frost shell using the supplied Ice texture, with the block color still identifiable.
- Actual: Both the alpha baseline and disabled-clip baseline use constant zero, making the shell invisible while the separate UI counter remains visible.
- Confirmed cause: `Vector1Node` constructs its input slot with zero. Updating its private legacy `m_Value` field and rebuilding slots preserves the existing input value. Generated shader code reads the input slot, not that field.
- Repair boundary: Set the actual scalar input value through the pinned Shader Graph API; narrowly regenerate the already approved Ice graph/material, retain all other assets, and verify rendered pixels rather than property presence alone.
