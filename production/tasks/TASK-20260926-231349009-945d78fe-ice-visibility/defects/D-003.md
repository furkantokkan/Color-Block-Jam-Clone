## Observation

The Ice integration replaced the loader's existing library-only converter call with an unconditional `Resolve<BlockShapeCatalog>()`. The current ProjectContext leaves `ProjectScopeInstaller.m_shapeLibrary` unassigned, so that installer deliberately registers no catalog. Onity automatic construction reaches an empty library and throws before a Game attempt starts.

## Reproduction

1. Run any of the three real Game scene tests against the current project assets.
2. Load Game and await its scene scope build.
3. `GameAttemptLoader.Load` resolves the unregistered concrete catalog; the inner exception reports that the piece-library JSON source is missing.

## Expected and actual

- Expected: Preserve the existing scene library conversion when no project catalog is registered, and use the registered catalog when project shape loading is enabled.
- Actual: Game startup aborts. The canonical library JSON GUID resolves correctly and its live TextAsset contains 3,739 characters; the authored reference is not missing or corrupt.
- Repair boundary: Existing GameAttemptLoader and Ice tests only. No ProjectContext, authored library, package, converter or session change.
